# 홈 서머리 이유식 전환 PRD

## 1. 배경

현재 홈 화면은 `마지막 수유`, `다음 수유 예측`, `수유량`, `수유 간격` 중심으로 구성되어 있다.  
이 구조는 수유만 하는 아기에게는 적합하지만, 이유식을 시작한 이용자에게는 정보 중심이 수유에만 치우쳐 있다.

분석탭과 동일한 원칙으로, 홈 화면에서도 `수유하는 아기`와 `이유식을 하는 아기`를 분리해서 판단해야 한다.

## 2. 문제 정의

- 이유식을 시작한 뒤에도 홈 메인 서머리가 수유 기준으로 유지된다.
- 보호자가 홈에서 가장 먼저 보고 싶은 정보가 이유식으로 이동했는데, 화면은 여전히 수유 예측을 전면에 둔다.
- 수유와 이유식이 병행되는 경우에도 우선순위가 정의되어 있지 않아, 정보 구조가 혼재된다.

## 3. 목표

- 이유식을 1회라도 시작한 아기라면 홈 서머리의 메인을 이유식 중심으로 전환한다.
- 기존 수유 로직은 수정하지 않고 그대로 유지한다.
- 이유식 시작 이후에는 수유 서머리를 보조 정보로 내린다.
- 홈에서만 노출 우선순위를 바꾸고, 다른 화면의 로직은 침범하지 않는다.

## 4. 비목표

- 수유 알림 로직 변경
- 수유량 계산식 변경
- 수유 예측 알고리즘 수정
- 이유식 전용 DB 스키마 강제 추가
- 분석탭과 홈의 기준을 하나로 합치는 작업

## 5. 핵심 개념 정의

- `수유 아기`: 수유 기록이 존재하는 아기
- `이유식 시작 아기`: 이유식 기록이 1회 이상 존재하는 아기
- `이유식 활성 아기`: 이유식 기록이 누적되어 홈 메인 서머리로 보여줄 수 있는 아기
- `이유식 데이터 부족`: 이유식은 시작했지만 패턴 판단에 필요한 기록이 부족한 상태
- `수유 서머리`: 기존 홈의 수유 중심 카드와 예측 정보
- `이유식 서머리`: 이유식 중심 카드와 요약 정보

## 6. 상태 분리 원칙

- `수유 중`과 `이유식 시작`은 상호 배타가 아니다.
- 이유식을 시작해도 수유는 계속될 수 있다.
- 홈에서는 이유식 시작 여부만으로 메인 서머리 우선순위를 판단한다.
- 수유 서머리는 삭제하지 않고 보조 정보로 유지한다.

## 7. 노출 우선순위

### 7.1 이유식 미시작

- 홈 메인 헤드라인은 수유 기준으로 유지한다.
- 마지막 기록 카드, 다음 예측 카드, 오늘 요약 카드 모두 수유 중심으로 유지한다.

### 7.2 이유식 시작 직후

- 홈 메인 헤드라인을 이유식 중심으로 전환한다.
- 마지막 기록 카드도 이유식 중심이 우선이다.
- 수유 예측은 메인에서 제외하고 보조 정보로 내린다.
- 이유식 데이터가 부족하면 `기록을 더 쌓는 중` 상태를 보여준다.

### 7.3 이유식 활성

- 홈 메인 헤드라인은 이유식 기준으로 고정한다.
- 이유식량, 이유식 간격, 마지막 이유식 시각을 우선 노출한다.
- 수유 관련 서머리는 보조 카드 또는 접이식 정보로 유지한다.

## 8. 홈 카드 구성안

### 8.1 상단 헤드라인

- 이유식 미시작: `오늘의 수유 리듬`
- 이유식 시작 이후: `오늘의 이유식 리듬`
- 이유식 시작 이후에는 수유 관련 카피를 메인 문구로 두지 않는다.

### 8.2 마지막 기록 카드

- 이유식 미시작: `마지막 수유`, `다음 수유 예측`
- 이유식 시작 이후: `마지막 이유식`, `오늘의 이유식 흐름`
- 이유식 시작 직후에는 정확한 예측이 어려우므로, `다음 예측` 대신 `예측보다 오늘 기록을 먼저 보여줘요` 같은 안내형 카피로 대체한다.
- 이유식이 1회뿐인 경우에는 `첫 이유식을 기록하면 오늘의 흐름이 보여요`처럼 학습 상태를 표현한다.

### 8.3 오늘 요약 카드

- 이유식 미시작: `수유량`, `수면시간`
- 이유식 시작 이후: `이유식량`, `수면시간`
- 수유량은 삭제하지 않고 보조 요약으로 내린다.
- 이유식 시작 이후 첫 번째 메인 요약은 `오늘 몇 회 / 총 몇 g`처럼 기록 흐름 중심으로 보여준다.

### 8.4 간격 카드

- 이유식 미시작: `수유 간격`
- 이유식 시작 이후: `이유식 간격`
- 이유식 간격은 기록이 충분하지 않으면 `기록 부족`으로 처리한다.

## 9. 이유식 관점에서 필요한 정보

이유식을 먹이는 엄마 관점에서 홈 화면에 필요한 정보는 아래와 같다.

- 오늘 이유식을 몇 번 먹였는지
- 총 몇 g을 먹였는지
- 마지막 이유식이 언제였는지
- 다음 이유식까지 얼마나 남았는지
- 이유식 간격이 일정한지
- 오전, 오후, 저녁 중 어디에 몰리는지
- 수유보다 이유식이 오늘의 중심인지
- 이유식 시작 직후인지, 패턴이 형성된 상태인지
- 새 식재료 반응을 확인해야 하는지

## 10. 수유와 이유식 병행 시 정책

- 이유식이 시작되면 홈 메인은 이유식으로 전환한다.
- 수유는 삭제하지 않고 보조 정보로 유지한다.
- 병행 상태에서는 다음 순서를 권장한다.
  - 메인: 이유식
  - 서브: 수유
  - 보조: 수면
- 사용자가 혼란스럽지 않도록 카드 제목에 `이유식 기준`, `수유 기준`을 명확히 구분한다.

## 11. 이유식 시작/활성/데이터 부족 기준

- 시작 기준
  - 이유식 기록 1회 이상
- 활성 기준
  - 이유식 기록이 누적되어 간격과 총량을 비교할 수 있는 상태
  - 예: 2회 이상 또는 2일 이상 등 서비스 정책으로 확정
- 데이터 부족 기준
  - 이유식 시작은 했으나 기록이 적어 평균 간격과 시간대 분포를 판단하기 어려운 상태

## 12. 예외 케이스

- 이유식을 1회만 기록한 경우
- 수유는 많지만 이유식은 드문 경우
- 같은 날 수유와 이유식이 모두 있는 경우
- 이유식 기록은 있으나 양이 없는 경우
- 이유식을 시작했지만 며칠간 기록이 없는 경우
- 이유식이 다시 중단되었다가 재개된 경우

## 13. 개발 전달용 구현 원칙

- 수유 계산 로직은 수정하지 않는다.
- 이유식은 별도 상태 또는 별도 판정 레이어로 처리한다.
- 홈 화면 렌더링 시에만 `수유 메인` vs `이유식 메인`을 결정한다.
- 다른 화면으로 우선순위 규칙이 확장되지 않도록 한다.
- 이벤트 기반 판정을 우선 사용하고, 필요 시 `solid_started_at` 같은 별도 속성을 추가하더라도 수유와 분리한다.
- 기존 수유 알림, 수유량 계산, 수유 문구는 침범하지 않는다.

## 14. 수용 기준

- 이유식 기록이 1회 이상이면 홈 서머리의 메인이 이유식 중심으로 바뀐다.
- 이유식 시작 이전 날짜와 사용자에게는 기존 수유 홈이 그대로 보인다.
- 이유식 시작 후에도 수유 서머리는 삭제되지 않고 보조 정보로 남는다.
- 이유식 데이터가 부족하면 `학습 중` 또는 `기록 부족` 상태가 보여야 한다.
- 수유 관련 기존 로직과 알림은 그대로 유지되어야 한다.

## 15. 구현 메모

- 분석탭과 홈은 같은 상태 정의를 공유할 수 있지만, 노출 우선순위는 각각 독립적으로 구현한다.
- 홈은 사용자가 가장 먼저 보는 화면이므로, 이유식 시작 직후부터 메인 문구와 카드 순서를 바꾸는 편이 가장 직관적이다.
- 다만 수유 사용자를 위한 기존 정보는 하위 카드로 유지해, 회귀를 막는다.
