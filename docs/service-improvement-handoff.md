# Infant Time Service Improvement Handoff

## 1. 문서 목적

현재 Infant Time은 홈에서 기록하고, 패턴에서 하루의 리듬을 보고, 분석에서 최근 추세를 해석하는 핵심 구조가 이미 잘 잡혀 있다. 특히 24시간 원형 리듬 차트와 수유·수면 분석은 다른 단순 기록 앱과 구분되는 자산이므로 대규모 화면 개편보다 반복 사용에서 생기는 작은 마찰을 줄이는 방향이 적합하다.

이 문서는 다음 원칙으로 실행 가능한 개선 백로그를 정리한다.

- 기록은 가능한 한 현재 시각 기준 2탭 이내에 저장한다.
- 상세 입력 능력은 유지하되, 평소에는 최근 선택과 기본값을 활용한다.
- 패턴과 분석은 새 차트를 늘리기보다 사용자가 의미 있는 변화와 원기록을 빠르게 찾게 한다.
- 데이터가 부족할 때 0으로 채운 차트를 길게 보여주지 않는다.
- 기존 디자인 언어, 하단 5개 탭, 원형 리듬 차트는 유지한다.

## 2. 현재 서비스 진단

### 유지해야 할 강점

- 홈에서 모유, 분유, 이유식, 수면, 기저귀 등 주요 기록으로 바로 진입할 수 있다.
- 입력 화면이 현재 시각과 최근 분유량을 기본값으로 사용하며 상세 수정도 지원한다.
- 패턴 탭이 수면, 수유, 기저귀, 세부 활동을 하나의 24시간 리듬으로 보여준다.
- 분석 탭이 당일 지표, 전날 차이, 최근 7일 추세를 함께 제공한다.
- 패턴과 분석이 같은 선택 날짜 상태를 공유하므로 두 화면을 오갈 때 맥락을 유지할 기반이 있다.
- 수면 시작·종료, 기록 수정·삭제, 자정 경계 처리 등 실사용에 필요한 데이터 동작이 이미 구현되어 있다.

### 확인된 작은 마찰

- 홈의 기록 버튼은 9개가 가로 스크롤 영역에 놓이지만 화면 끝에 추가 항목이 있다는 단서가 약하다.
- 사용 빈도와 상관없이 기록 버튼 순서가 고정되어 한 손 사용 시 자주 쓰는 항목이 화면 밖으로 밀릴 수 있다.
- 현재 입력 화면은 모든 기록에서 날짜, 시간, 메모 등 상세 필드를 먼저 보여준다. “지금, 평소 값으로 기록”하려는 사용자는 확인할 정보가 많다.
- 저장 성공 토스트는 결과만 알리고 방금 저장한 내용을 바로 되돌리거나 수정할 수 없다.
- 수면 중 상태는 홈 요약에 표시되지만 기록 버튼 자체의 의미는 계속 `수면`으로 보여 시작과 종료가 즉시 구분되지 않는다.
- 패턴과 분석의 날짜 이동은 날짜 입력에 의존해 전날과 다음 날을 연속해서 살펴보기 번거롭다.
- 기록이 없는 날에도 패턴 요약 카드 4개와 분석 차트 축·0 막대가 노출되어 화면은 길지만 얻는 정보는 적다.
- 패턴 차트에서 특정 구간을 발견해도 해당 원기록을 수정하려면 홈 최근 기록에서 다시 찾아야 한다.
- 분석은 많은 수치를 제공하지만 가장 중요한 변화와 그 변화에 기여한 기록이 분리되어 있다.

## 3. 우선순위 백로그

## P0. 반복 입력 마찰 줄이기

### P0-1. 기록 타입별 최근 입력값 재사용

**사용자 문제**

같은 분유량, 기저귀 세부값, 약 이름, 체온 위치, 이유식 종류처럼 반복되는 값을 매번 다시 선택해야 한다. 현재 분유량 일부만 최근 값이 반영되고 타입별 정책이 일관되지 않다.

**제안 동작**

- 아기별·기록 타입별 마지막 확정 입력값을 다음 신규 입력의 기본값으로 사용한다.
- 재사용 대상:
  - 분유량
  - 모유 좌우 시간은 재사용하지 않고 비워 둔다.
  - 기저귀 종류, 대변 양·색상
  - 약 이름·용량
  - 체온 측정 위치
  - 이유식 이름·양·반응
- 날짜와 시간은 항상 현재 시각을 기본으로 한다.
- 수정 화면의 값은 기존 기록값을 우선하며, 최근 기본값을 덮어쓰지 않는다.
- 기본값이 최근 기록에서 왔음을 필요한 경우 `최근 입력` 보조 문구로 짧게 표시한다.

**구현 영향 범위**

- `EventInputScreen`의 신규 입력 초기화 로직
- 아기별 이벤트 목록에서 타입별 최신 유효값을 찾는 selector 또는 helper
- 필요 시 localStorage에 저장하는 방식보다 현재 조회된 이벤트를 우선 사용

**수용 기준**

- 같은 아기에게 분유 기록 후 다시 분유 입력을 열면 직전 분유량이 선택되어 있다.
- 대변 기록 후 다시 기저귀 입력을 열면 직전 기저귀 종류와 대변 상세값이 복원된다.
- 다른 아기로 전환하면 이전 아기의 기본값이 섞이지 않는다.
- 기록 수정 시에는 최근 값이 아니라 수정 대상 기록값이 표시된다.
- 모유 시간, 기록 시각, 메모는 의도치 않게 재사용되지 않는다.

**예상 효과**

- 반복 기록의 선택 횟수 감소
- 사용자가 평소 기록을 빠르게 저장하면서도 예외 상황만 수정 가능

**위험 및 대응**

- 오래된 값이 무심코 저장될 수 있다. 날짜·시간과 자유 텍스트 메모는 재사용하지 않고, 의료적으로 민감할 수 있는 체온 숫자도 비워 둔다.

### P0-2. 최근 사용 기반 빠른 기록 순서

**사용자 문제**

고정된 9개 기록 순서 때문에 사용자마다 자주 쓰는 항목이 첫 화면 밖에 위치할 수 있다.

**제안 동작**

- 기본 순서는 현재 순서를 유지한다.
- 최근 14일 또는 최근 30회 기록에서 사용 빈도와 최근성을 계산해 상위 4개를 첫 화면에 배치한다.
- 모유와 분유는 별도 액션으로 유지한다.
- 새 사용자와 데이터가 부족한 사용자는 기본 순서를 사용한다.
- 순서 변경은 조용히 적용하고 별도의 설정 화면은 만들지 않는다.
- 버튼 위치가 매번 흔들리지 않도록 이벤트가 저장될 때만 순서를 다시 계산한다.

**구현 영향 범위**

- `SummaryCards`의 `quickActions` 정렬
- 이벤트 타입과 수유 방식별 최근 사용 점수 계산 helper
- 선택적으로 아기별 계산 결과를 localStorage에 캐시

**수용 기준**

- 기록 이력이 없는 아기는 기존 기본 순서를 본다.
- 특정 액션을 반복 사용하면 다음 앱 진입 또는 저장 이후 첫 4개 안으로 이동한다.
- 동일한 이벤트 목록에서는 렌더링할 때마다 순서가 바뀌지 않는다.
- 접근성 이름, 아이콘, 클릭 시 열리는 입력 타입은 순서 변경 후에도 정확하다.

**예상 효과**

- 한 손 사용 시 가로 스크롤 없이 주요 기록 접근
- 사용자별 기록 습관을 별도 설정 없이 반영

**위험 및 대응**

- 버튼 위치 학습이 깨질 수 있다. 갱신 시점을 저장 완료 시점으로 제한하고, 상위 항목의 점수 차이가 작으면 기존 순서를 유지하는 안정화 규칙을 둔다.

### P0-3. 저장 직후 `수정`과 `취소` 액션 제공

**사용자 문제**

현재 저장 완료 토스트는 성공 여부만 알려준다. 잘못된 분유량이나 기록 타입을 저장하면 최근 기록까지 내려가 다시 찾거나 삭제해야 한다.

**제안 동작**

- 저장 후 4~5초 동안 하단 또는 상단의 비차단 스낵바를 표시한다.
- 신규 저장: `분유 130ml를 기록했어요`와 `수정`, `취소` 제공
- 수정 저장: `기록을 수정했어요`와 `다시 수정` 제공
- `수정`은 방금 저장된 이벤트를 입력 모달로 연다.
- `취소`는 방금 생성된 이벤트만 삭제하고 `기록을 취소했어요`로 피드백한다.
- 새 저장이 발생하면 이전 스낵바를 교체하며, 취소 가능 이벤트 ID도 최신 항목으로 갱신한다.

**구현 영향 범위**

- `addEvent`가 생성된 `BabyEvent`를 호출자에게 반환하도록 hook/repository 반환값 확인 및 연결
- `App`의 단순 문자열 토스트를 액션 가능한 save result 상태로 확장
- 입력 모달 재열기 및 삭제 성공·실패 처리

**수용 기준**

- 신규 저장 후 방금 저장한 이벤트의 타입과 핵심 값이 스낵바에 표시된다.
- `수정`을 누르면 해당 이벤트의 값이 채워진 수정 모달이 열린다.
- `취소`를 누르면 해당 이벤트만 삭제되고 홈, 패턴, 분석 요약이 즉시 갱신된다.
- 취소 요청 실패 시 이벤트는 유지되고 오류 메시지가 표시된다.
- 화면 읽기 도구가 메시지와 액션을 인식할 수 있다.

**예상 효과**

- 오입력에 대한 불안 감소
- 빠른 기록을 더 과감하게 사용할 수 있어 입력 완료율 향상

**위험 및 대응**

- Supabase 지연 중 중복 삭제가 발생할 수 있다. 취소 처리 중 버튼을 비활성화하고 이벤트 ID 단위로 한 번만 처리한다.

### P0-4. 진행형 기록의 상태 기반 홈 액션

**사용자 문제**

수면 또는 놀이가 진행 중이어도 빠른 기록 버튼의 라벨은 동일해 “새 기록 시작”인지 “현재 기록 종료”인지 바로 알기 어렵다.

**제안 동작**

- 진행 중 수면이 있으면 홈 버튼을 `깨우기` 또는 `수면 종료`로 바꾸고 경과 시간을 함께 표시한다.
- 진행 중 놀이가 있으면 `놀이 종료`와 경과 시간을 표시한다.
- 상태 기반 버튼은 입력 모달을 거치지 않고 한 번의 확인 가능한 액션으로 현재 시각에 종료한다.
- 실수 방지를 위해 저장 후 취소 가능한 스낵바를 제공한다.
- 진행 중 기록이 없으면 기존 `수면`, `놀이` 버튼 동작을 유지한다.
- 홈 요약의 `깨우기`와 빠른 기록 버튼은 동일한 종료 함수를 사용한다.

**구현 영향 범위**

- `SummaryCards` 빠른 액션 모델에 진행 상태와 경과 시간 전달
- 수면 종료 로직 일반화 및 놀이 종료 로직 추가
- 취소를 위해 종료 전 `endedAt` 값을 보관하거나 수정 스낵바 제공

**수용 기준**

- 진행 중 수면이 없을 때 `수면`을 누르면 기존 입력 흐름이 열린다.
- 진행 중 수면이 있을 때 버튼 라벨과 시각적 상태가 종료 액션임을 명확히 나타낸다.
- 종료 액션 한 번으로 현재 시각이 저장되고 모든 요약이 갱신된다.
- 진행 중 이벤트가 둘 이상인 비정상 데이터에서도 종료 대상이 명확하며 중복 종료하지 않는다.

**예상 효과**

- 가장 시간에 민감한 수면 시작·종료 동선 단축
- 열린 기록을 잊어 수면 시간이 과대 집계되는 문제 감소

**위험 및 대응**

- 실수로 종료할 가능성이 있다. 즉시 확인 모달을 추가해 탭 수를 늘리기보다 P0-3의 취소 액션으로 복구 가능하게 한다.

## P1. 패턴 탭의 발견과 행동 연결

### P1-1. 전날·오늘·다음 날 빠른 이동

**사용자 문제**

날짜 입력은 특정 날짜 선택에는 유용하지만 어제와 오늘을 연속 비교할 때 조작이 크다.

**제안 동작**

- 패턴과 분석 상단에 공통 날짜 내비게이션을 사용한다.
- 구성: 이전 날 버튼, 현재 선택 날짜, 다음 날 버튼, 선택 날짜가 오늘이 아닐 때 `오늘` 버튼
- 미래 날짜 이동은 기본적으로 막는다.
- 네이티브 날짜 입력은 날짜 텍스트 또는 달력 아이콘을 눌러 계속 사용할 수 있다.
- 패턴과 분석은 현재처럼 하나의 선택 날짜 상태를 공유한다.

**구현 영향 범위**

- 공통 `DateNavigator` 컴포넌트
- `App`의 공유 `analysisDate` 상태 유지
- `AnalysisCards`, `PatternCards`의 날짜 header 교체

**수용 기준**

- 이전·다음 버튼 한 번으로 정확히 하루씩 이동한다.
- 패턴에서 날짜를 바꾸고 분석 탭으로 이동하면 같은 날짜가 선택되어 있다.
- 오늘보다 미래로 이동할 수 없다.
- 오늘이 아닌 날짜에서는 `오늘` 버튼이 보이고 한 번에 오늘로 돌아온다.
- 로컬 시간대를 기준으로 날짜 경계가 계산된다.

**예상 효과**

- 리듬과 분석의 반복 탐색 속도 향상
- 두 강점 탭을 하나의 연결된 경험으로 인식

**위험 및 대응**

- 자정 전후 UTC 변환 오류가 생길 수 있다. ISO 문자열의 UTC 날짜가 아니라 로컬 연·월·일 helper를 사용한다.

### P1-2. 리듬 차트에서 원기록 열기

**사용자 문제**

패턴 차트에서 이상 구간이나 잘못된 시간을 발견해도 원기록을 다시 찾아야 한다.

**제안 동작**

- 원형 차트의 segment와 시간대별 리듬 pill을 선택 가능하게 만든다.
- 선택 시 타입, 시작·종료 시각, 핵심 상세값을 담은 작은 상세 카드 또는 bottom sheet를 연다.
- 상세 카드에서 `기록 수정`을 누르면 기존 `EventInputScreen` 수정 모달을 연다.
- 같은 시간에 겹친 기록은 목록으로 보여 사용자가 대상을 선택한다.
- 키보드와 화면 읽기 도구에서도 기록을 선택할 수 있게 한다.

**구현 영향 범위**

- `RhythmSegment`에 원본 이벤트 ID 유지
- `PatternCards`에 `onEditEvent` 또는 `onSelectEvent` callback 추가
- `App`의 기존 `handleEditEvent` 재사용
- SVG segment의 focus, label, hit area 보완

**수용 기준**

- 차트와 타임라인에서 선택한 기록의 상세값이 정확히 표시된다.
- `기록 수정`은 해당 이벤트 ID의 수정 모달을 연다.
- 수정 저장 후 원형 차트, 타임라인, 패턴 요약, 홈과 분석이 즉시 갱신된다.
- 작은 point 이벤트도 최소 44px에 준하는 선택 영역 또는 대체 목록 접근 경로가 있다.

**예상 효과**

- 패턴 탭이 단순 조회 화면에서 기록 품질을 개선하는 작업 공간으로 확장
- 잘못된 시간 때문에 분석 결과가 왜곡되는 문제를 사용자가 직접 해결

**위험 및 대응**

- SVG의 작은 segment는 터치하기 어렵다. 시각적 arc 두께를 과도하게 키우지 않고 투명 hit path 또는 타임라인 대체 선택을 제공한다.

### P1-3. 기록량에 따른 빈 상태 단계화

**사용자 문제**

기록 0개인 날에도 0회·0분 카드가 반복되고, 분석에서는 의미 없는 0 막대와 축이 길게 표시된다.

**제안 동작**

- 데이터 상태를 `empty`, `sparse`, `ready`로 구분한다.
- 패턴:
  - `empty`: 원형 빈 상태와 한 개의 설명, `첫 기록 남기기` CTA만 표시
  - `sparse`: 실제 기록이 있는 항목만 요약하고 “기록이 더 쌓이면 비교가 시작됩니다” 안내
  - `ready`: 현재 전체 리듬, 인사이트, 요약 표시
- 분석:
  - 해당 차트의 최소 데이터 조건을 충족하지 못하면 차트 축과 0 막대를 숨긴다.
  - 필요한 기록 조건과 바로 기록할 수 있는 CTA를 표시한다.
- CTA는 사용자가 보던 날짜를 기본 시각으로 입력 모달에 전달할 수 있어야 한다. 과거 날짜라면 현재 시각 대신 선택 날짜의 적절한 기본 시각을 명확히 정의한다.

**구현 영향 범위**

- 패턴·분석 데이터 준비도 helper
- 빈 상태 컴포넌트와 입력 callback
- 선택 날짜 기반 신규 입력 시각 정책

**수용 기준**

- 기록 0개에서는 0 값 카드와 7일 0 막대가 반복 노출되지 않는다.
- 기록 1개에서는 해당 기록과 다음에 필요한 데이터만 설명한다.
- 최소 조건을 충족하면 기존 차트가 자동으로 나타난다.
- 빈 상태 CTA가 올바른 기록 타입의 입력 화면을 연다.

**예상 효과**

- 초반 사용자의 인지 부담 감소
- “분석할 것이 없다”가 아니라 “무엇을 기록하면 가치가 생기는지” 안내

**위험 및 대응**

- 차트가 갑자기 나타나 레이아웃이 변할 수 있다. 상태별 전환은 자연스럽게 하되 고정 placeholder 높이를 강제해 빈 공간을 만들지는 않는다.

### P1-4. 평소와 다른 시간대의 은은한 강조

**사용자 문제**

현재 인사이트 문구는 차이를 설명하지만 사용자가 원형 차트에서 어느 시간대가 평소와 달랐는지 직접 찾아야 한다.

**제안 동작**

- 최근 7일 중 데이터가 충분한 날을 기준으로 수유 시간대와 수면 구간의 일반 범위를 계산한다.
- 선택 날짜가 일반 범위에서 크게 벗어난 구간만 얇은 외곽선, 작은 점 또는 배경 halo로 강조한다.
- 강조는 `평소보다 긴 수유 공백`, `평소보다 늦은 첫 수유`, `평소보다 짧거나 긴 수면 구간`처럼 이미 계산 가능한 관찰에 한정한다.
- 범례 또는 인사이트에 `평소와 다른 구간`의 의미를 설명한다.
- 데이터가 부족하면 비교 강조를 표시하지 않는다.

**구현 영향 범위**

- 기존 최근 7일 통계 계산 확장
- 비교 가능 최소 일수 및 임계값 상수
- `RhythmSegment`의 comparison 상태와 SVG 스타일

**수용 기준**

- 충분한 비교 데이터가 없는 사용자에게 이상 강조가 나타나지 않는다.
- 같은 데이터에서 강조 구간과 인사이트 문구가 모순되지 않는다.
- 색상만으로 차이를 전달하지 않고 설명 문구 또는 아이콘을 함께 제공한다.
- 의료적 진단이나 위험 판정 문구를 사용하지 않는다.

**예상 효과**

- 원형 리듬 차트의 차별점을 더 쉽게 체감
- 차트 해석에 필요한 시간을 줄이면서 과도한 신규 기능은 피함

**위험 및 대응**

- 정상적인 성장 변화가 이상처럼 보일 수 있다. `이상`, `경고` 대신 `평소와 다른 흐름`이라는 중립 표현을 사용하고 임계값은 보수적으로 설정한다.

## P1. 분석 탭의 해석 밀도 높이기

### P1-5. 데이터 조건 기반 차트 노출

**사용자 문제**

기록이 없는 상태에서도 7일 차트와 고정 축이 표시되어 정보보다 화면 길이가 커진다.

**제안 동작**

- 차트별 최소 조건을 명시하고 충족할 때만 실제 차트를 표시한다.
  - 당일 수유 타임라인: 선택 날짜 수유 1건 이상
  - 평균 간격: 선택 날짜 동일 타입 2건 이상
  - 7일 추세: 최근 7일 중 값이 있는 날 2일 이상
  - 대변 색상 분포: 색상이 기록된 대변 1건 이상
- 미충족 시 차트 대신 한 문장의 현재 상태, 필요한 기록 조건, 관련 입력 CTA를 표시한다.
- 조건은 UI 문구와 코드 상수에서 동일하게 관리한다.

**구현 영향 범위**

- `AnalysisCards`의 차트별 조건 분기
- 공통 부족 데이터 안내 컴포넌트
- 분석 CTA에서 `App.handleQuickAdd` 연결

**수용 기준**

- 모든 값이 0인 7일 막대 차트가 표시되지 않는다.
- 조건을 충족하는 즉시 새로고침 없이 차트가 표시된다.
- 안내 문구가 “기록 부족”만 말하지 않고 필요한 최소 기록을 알려준다.

**예상 효과**

- 분석 화면 길이와 시각적 소음 감소
- 사용자에게 다음 기록 행동을 구체적으로 안내

**위험 및 대응**

- 차트를 숨기면 기능 존재를 모를 수 있다. 빈 상태에 나타날 차트 이름과 생성 조건을 함께 보여준다.

### P1-6. 핵심 변화와 기여 기록을 먼저 보여주기

**사용자 문제**

현재 Insight, 핵심 카드, 차트가 각각 정보를 제공하지만 “무엇이 달라졌고 왜 그런지”를 한 번에 이해하기 어렵다.

**제안 동작**

- 분석 상단 Insight를 한 개의 주 변화와 최대 두 개의 근거로 구성한다.
- 예:
  - `수유 간격이 최근 평균보다 35분 길었어요`
  - 근거: `오후 2:10~6:05 사이 3시간 55분 공백`
  - 보조: `하루 총량은 최근 평균과 비슷해요`
- 근거 행을 누르면 해당 차트 또는 원기록 상세로 이동한다.
- 변화가 뚜렷하지 않으면 억지 인사이트 대신 `최근 흐름과 비슷해요`를 표시한다.
- 수유·수면·기저귀 중 가장 신뢰도 높은 한 항목만 상단 대표 인사이트로 선정한다.

**구현 영향 범위**

- 분석 인사이트 결과 타입에 근거, 관련 이벤트 ID, 대상 section 추가
- 최근 평균과 선택 날짜 차이 계산 정리
- section scroll 또는 이벤트 상세 callback

**수용 기준**

- 대표 인사이트는 실제 표시된 지표와 계산 결과가 일치한다.
- 근거가 없는 추측성 설명을 만들지 않는다.
- 관련 기록이 있으면 한 번의 액션으로 해당 기록 또는 상세 영역에 도달한다.
- 유의미한 변화가 없을 때 경고성 문구를 만들지 않는다.

**예상 효과**

- 많은 차트를 읽지 않아도 선택 날짜의 핵심을 이해
- 분석 탭의 차별점이 “차트 수”가 아니라 “설명 가능한 변화”로 강화

**위험 및 대응**

- 임계값에 따라 문구가 자주 바뀔 수 있다. 최소 변화량과 데이터 신뢰도 조건을 상수로 정의하고 단위 테스트를 추가한다.

### P1-7. 패턴·분석 간 동일 맥락 이동

**사용자 문제**

날짜 상태는 공유되지만 사용자가 분석에서 발견한 시간대나 기록을 패턴에서 이어서 볼 수는 없다.

**제안 동작**

- 분석의 근거 기록에서 `리듬에서 보기` 액션을 제공한다.
- 이동 시 같은 날짜의 패턴 탭을 열고 관련 segment 또는 시간대를 강조한다.
- 패턴에서 `분석에서 보기`를 선택하면 같은 날짜와 관련 분석 section을 연다.
- 강조 상태는 일회성이며 다른 날짜 또는 탭 이동 후에는 제거한다.

**구현 영향 범위**

- `App`에 선택 날짜 외 `focusEventId` 또는 `focusTimeRange` 상태 추가
- 탭 변경 callback에 focus context 전달
- 패턴 segment 강조와 분석 section focus 처리

**수용 기준**

- 분석에서 패턴으로 이동해도 날짜가 바뀌지 않는다.
- 관련 이벤트 또는 시간대가 스크롤·강조되어 사용자가 바로 찾을 수 있다.
- 존재하지 않거나 삭제된 이벤트 ID는 오류 없이 일반 패턴 화면으로 열린다.

**예상 효과**

- 두 강점 탭이 별도 보고서가 아니라 하나의 탐색 흐름으로 연결

**위험 및 대응**

- 상태 관리가 복잡해질 수 있다. URL 라우팅을 새로 도입하지 않고 `App`의 짧은 일회성 focus state로 제한한다.

## P2. 세부 사용성 및 신뢰도

### P2-1. 빠른 기록 가로 스크롤 단서

**사용자 문제**

첫 화면에 보이는 네 개 이후에 다른 기록 버튼이 있다는 사실이 명확하지 않다.

**제안 동작**

- 오른쪽 끝 다음 카드가 12~20px 정도 보이도록 카드 폭과 gap을 조정한다.
- 스크롤 가능한 경우에만 오른쪽 edge fade 또는 작은 `더 보기` 단서를 표시한다.
- 사용자가 끝까지 스크롤하면 단서를 숨긴다.
- 스크롤 위치와 상관없이 하단 탭과 겹치지 않는다.

**구현 영향 범위**

- `home-quick-grid` CSS
- 필요 시 scroll position을 감지하는 최소 상태

**수용 기준**

- 375px와 390px 폭에서 다음 항목의 존재가 시각적으로 드러난다.
- 가로 스크롤 중 세로 페이지 스크롤이 부자연스럽게 막히지 않는다.
- 마지막 항목에서는 오른쪽 fade가 사라진다.

**예상 효과**

- 숨겨진 기록 타입 발견 가능성 향상

**위험 및 대응**

- 과도한 gradient가 버튼을 가릴 수 있다. 클릭 영역과 겹치지 않는 장식 레이어로 구현한다.

### P2-2. 빈 상태·오류·삭제 피드백 정리

**사용자 문제**

기록이 없는 상태와 저장·삭제 실패 상태가 화면마다 서로 다른 밀도와 문구로 제공된다. 스와이프 삭제는 복구 경로가 약하다.

**제안 동작**

- 빈 상태를 `제목 + 한 문장 + 선택적 CTA` 구조로 통일한다.
- 네트워크 오류는 현재 데이터가 유지되는지, 재시도 가능한지 구분해 안내한다.
- 삭제 후에도 P0-3과 같은 짧은 `되돌리기` 액션을 제공한다.
- 성공 메시지는 구체적인 타입과 결과를 말하고, 일반적인 `저장이 완료되었습니다` 문구를 줄인다.
- 실패 시 입력 모달을 닫지 않고 사용자의 작성값을 보존한다.

**구현 영향 범위**

- 공통 feedback/snackbar 상태
- `EventList` 삭제 흐름
- 저장·수정 예외 처리 및 입력 모달 상태

**수용 기준**

- 저장 실패 시 입력값이 사라지지 않는다.
- 삭제 후 제한 시간 안에 되돌리면 동일 이벤트가 복원된다.
- 오류 메시지가 수행하지 못한 작업과 다음 행동을 설명한다.

**예상 효과**

- 기록 데이터에 대한 신뢰 상승
- 실수 복구를 위해 고객지원이나 수동 재입력을 할 필요 감소

**위험 및 대응**

- 삭제 복원 시 원래 ID 재생성이 저장소별로 어려울 수 있다. repository의 create/update 계약을 확인해 원본 필드를 복원하되 ID 유지가 불가능하면 새 ID 생성 사실이 집계에 영향을 주지 않는지 검증한다.

### P2-3. 광고 배치가 핵심 흐름을 끊지 않도록 조정

**사용자 문제**

홈 기록 영역 직전이나 분석의 핵심 지표와 상세 전환 사이에 광고가 들어오면 기록 및 해석의 흐름이 끊길 수 있다.

**제안 동작**

- 입력 모달, 진행형 기록 종료, 저장 피드백 중에는 현재처럼 광고를 숨긴다.
- 홈에서는 빠른 기록과 최근 기록 사이를 광고로 분리하지 않는다.
- 분석에서는 Insight, 핵심 지표, 상세 항목 전환을 하나의 연속 영역으로 유지하고 광고는 첫 완결된 분석 section 이후에 둔다.
- 패턴의 원형 차트와 시간대별 리듬 사이에는 광고를 넣지 않는다.
- 광고 로딩 실패 시 빈 높이를 남기지 않는다.

**구현 영향 범위**

- `AdBanner` placement 위치
- AdMob native banner 가시성 이벤트 조건
- 광고 높이와 로딩 실패 CSS

**수용 기준**

- 홈의 핵심 기록 버튼은 광고보다 먼저 도달 가능하다.
- 분석의 대표 Insight와 관련 상세 전환 사이에 광고가 끼지 않는다.
- 광고 로딩 성공·실패 모두 레이아웃 점프가 과도하지 않다.
- 광고 정책과 실제 클릭 영역을 침해하지 않는다.

**예상 효과**

- 수익화 구조를 유지하면서 핵심 기능의 연결감 개선

**위험 및 대응**

- 노출 수가 달라질 수 있다. 변경 전후 placement별 노출과 사용자 행동을 함께 관찰하되, 기록 완료율과 분석 상세 진입률을 우선 지표로 둔다.

## 4. 권장 구현 순서

1. 공통 피드백 모델과 생성 이벤트 반환 계약을 정리한다.
2. P0-1 최근 입력 기본값과 P0-4 진행형 기록 종료를 구현한다.
3. P0-3 저장·삭제 수정/취소 스낵바를 연결한다.
4. P0-2 빠른 기록 순서와 P2-1 스크롤 단서를 적용한다.
5. 공통 날짜 내비게이션과 패턴·분석 공유 날짜를 정리한다.
6. 데이터 준비도 상태를 도입해 패턴·분석의 0 차트를 줄인다.
7. 패턴 segment의 원기록 연결을 구현한다.
8. 분석 대표 인사이트와 패턴·분석 focus 이동을 구현한다.
9. 비교 데이터가 충분한 경우에만 평소와 다른 리듬 강조를 추가한다.
10. 광고 placement와 전체 모바일 회귀 테스트를 수행한다.

P0 항목은 각각 독립 배포할 수 있다. P1-2, P1-6, P1-7은 이벤트 focus 모델을 공유하므로 같은 설계 묶음으로 진행하는 편이 안전하다.

## 5. 공통 인터페이스 제안

구현 시 이름은 현재 코드 스타일에 맞게 조정할 수 있지만 책임은 아래처럼 분리한다.

```ts
type DataReadiness = "empty" | "sparse" | "ready";

interface FeedbackAction {
  label: string;
  onClick: () => void | Promise<void>;
}

interface AppFeedback {
  id: string;
  message: string;
  tone: "success" | "error" | "neutral";
  primaryAction?: FeedbackAction;
  secondaryAction?: FeedbackAction;
  expiresInMs?: number;
}

interface AnalysisFocus {
  dateKey: string;
  eventId?: string;
  startMinute?: number;
  endMinute?: number;
  section?: "intake" | "sleep" | "diaper";
}
```

- `addEvent`는 생성 완료된 `BabyEvent`를 반환해야 한다.
- 패턴과 분석은 `selectedDate`, `onDateChange`, 선택적 focus context를 공통 계약으로 사용한다.
- 신규 입력 기본값 계산은 UI 컴포넌트 내부에 중복하지 않고 순수 helper로 분리한다.
- 데이터 준비도와 분석 임계값은 화면 문구와 테스트가 같은 상수를 참조하게 한다.

## 6. 검증 계획

### 입력 동선

- 375px, 390px 폭에서 모유, 분유, 수면, 기저귀 주요 기록을 홈 진입 후 기본 2탭 이내에 저장한다.
- 최근 분유량, 기저귀 상세, 약 정보, 체온 위치, 이유식 선택이 아기별로 올바르게 재사용되는지 확인한다.
- 모유 시간, 메모, 체온 숫자는 의도치 않게 재사용되지 않는지 확인한다.
- 진행 중 수면과 놀이의 시작·종료 라벨, 경과 시간, 취소 동작을 확인한다.
- 저장·수정·삭제 실패 시 작성값과 기존 이벤트가 보존되는지 확인한다.

### 패턴과 분석

- 기록 0개, 1개, 최소 조건 직전, 충분한 데이터 상태를 각각 확인한다.
- 기록이 없을 때 0 카드와 0 차트가 불필요하게 반복되지 않는지 확인한다.
- 전날, 다음 날, 오늘 이동과 미래 날짜 제한을 확인한다.
- 패턴에서 선택한 날짜가 분석에서도 유지되고 반대 방향도 같은지 확인한다.
- 원형 segment와 타임라인에서 같은 이벤트 상세가 열리는지 확인한다.
- 원기록 수정 후 패턴, 분석, 홈, 최근 기록의 값이 즉시 일치하는지 확인한다.
- 삭제된 focus 이벤트로 이동해도 앱이 오류 없이 일반 화면을 보여주는지 확인한다.
- 최근 데이터가 부족할 때 평소 비교 강조가 나타나지 않는지 확인한다.

### 모바일·접근성·광고

- 빠른 기록의 다음 카드 단서와 가로 스크롤이 세로 스크롤을 방해하지 않는지 확인한다.
- 하단 탭, 입력 모달 고정 저장 버튼, safe-area가 겹치지 않는지 확인한다.
- 차트 segment, 날짜 이동, 스낵바 액션을 키보드와 화면 읽기 도구로 사용할 수 있는지 확인한다.
- 광고 로딩 성공, 실패, 입력 모달 표시 상태에서 빈 공간과 레이아웃 점프를 확인한다.
- `npm run build`와 iOS/Android 실기기에서 주요 회귀 흐름을 확인한다.

## 7. 측정 권장 지표

분석 도구를 새로 도입하는 범위는 아니지만, 이벤트 측정이 가능하다면 아래 지표로 개선 효과를 확인한다.

- 홈 기록 버튼 선택부터 저장 완료까지의 중앙 시간
- 기록 1건당 입력 필드 변경 횟수
- 저장 후 10초 이내 수정·삭제 비율
- 시작 후 12시간 이상 종료되지 않은 수면·놀이 기록 비율
- 패턴·분석 날짜 이동 사용률
- 패턴 또는 분석에서 원기록 수정으로 이어진 비율
- 분석 탭의 상세 항목 진입률
- 광고 placement 변경 전후 기록 완료율

## 8. 제외 범위

- 하단 탭 구조 변경 또는 패턴·분석 통합
- 원형 리듬 차트의 전면 교체
- 신규 의료 진단, 위험도 판정, 정상 범위 단정
- 생성형 AI 기반 육아 조언 또는 자동 해석
- 입력 타입의 대규모 추가
- 데이터베이스 스키마를 먼저 요구하는 장기 리포트 기능
- 설정 화면을 늘리는 수동 커스터마이징

## 9. 완료 정의

- P0 개선 후 주요 반복 기록이 기본 2탭 이내에 완료되고 실수 복구 경로가 제공된다.
- 패턴과 분석의 기록 부족 상태가 실제 데이터 양에 맞게 간결하게 표시된다.
- 패턴 차트와 분석 근거에서 원기록 수정까지 직접 연결된다.
- 두 탭 사이에서 날짜와 선택 맥락이 유지된다.
- 기존 디자인과 원형 리듬 차트의 강점을 유지하며 모바일 빌드와 주요 회귀 테스트가 통과한다.
