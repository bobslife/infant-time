# Infant Time Next Service Handoff

작성일: 2026-06-19

## 1. 문서 목적

현재 Infant Time은 기록 생성·수정·삭제, 최근 값 재사용, 저장 취소, 수면·놀이 진행 상태, 날짜별 리듬, 분석, 성장 기록, 보호자 초대, 수유 리마인드, 네이티브 광고·위젯 기반까지 갖춘 상태다.

다음 단계에서는 기록 종류를 무작정 늘리기보다 아래 순서로 서비스 완성도를 높이는 편이 적합하다.

1. 실제 출시와 운영이 가능한 상태를 만든다.
2. 공동육아 서비스에서 가장 중요한 데이터 신뢰와 보호자 간 맥락을 강화한다.
3. 사용자가 다시 방문할 이유가 되는 알림·리포트·성장 기능을 완성한다.
4. 사용 중 혼란을 만드는 작은 인터랙션을 다듬는다.

아래 10개 과제는 예상 범위와 서비스 영향이 큰 것부터 작은 것 순으로 정리했다. 기존 `service-improvement-handoff.md`에서 완료된 빠른 기록, 저장 취소, 빈 분석 화면, 원기록 연결 등은 중복 제안하지 않는다.

## 3. 상세 과제

## 1. Android 운영 출시 완료

### 현재 확인

- Android 프로젝트, FCM 코드, 홈 위젯, AdMob, CI 기반은 준비되어 있다.
- 실제 APK/AAB 컴파일, Firebase 운영 설정, 실기기 검증, Play 내부 테스트는 완료되지 않았다.
- 코드가 준비되어 있어도 이 단계가 끝나지 않으면 Android 사용자는 서비스를 사용할 수 없다.

### 제안 범위

- JDK 21 환경에서 `assembleDebug`, `bundleRelease`를 통과시킨다.
- Play App Signing과 업로드 키스토어를 설정한다.
- Firebase Android 앱, `google-services.json`, Supabase FCM secrets를 운영 환경에 연결한다.
- Android push migration과 Edge Function을 배포한다.
- Samsung One UI와 Pixel에서 기록 CRUD, 푸시, 위젯, 광고, 강제 업데이트를 검증한다.
- Play Console 내부 테스트와 Data safety, 개인정보처리방침, 스토어 등록정보를 완료한다.
- 출시 후 즉시 되돌릴 수 있도록 최소 지원 버전과 단계적 배포 기준을 정한다.

### 완료 기준

- 내부 테스트 AAB 설치와 로그인부터 기록 저장까지 핵심 흐름이 성공한다.
- 수유 리마인드가 실제 Android 기기에 한 번만 발송된다.
- 위젯이 저장·수정·로그아웃 후 올바르게 갱신된다.
- 광고가 입력 모달, 하단 탭, 저장 스낵바를 가리지 않는다.
- Play Console 출시 차단 항목이 모두 해소된다.

### 권장 측정

- 설치 성공률
- 로그인 완료율
- 첫 기록 완료율
- 푸시 권한 허용률과 실제 발송 성공률
- Android 크래시 없는 사용자 비율

## 2. 운영 관측성과 핵심 지표 구축

### 사용자·운영 문제

현재 코드에는 저장 실패 메시지와 일부 콘솔 로그가 있지만, 운영 환경에서 어떤 화면이 실패하는지, 사용자가 어디서 이탈하는지, 푸시가 왜 실패했는지를 한곳에서 확인하기 어렵다. 기능이 많아진 시점부터는 사용자 문의만으로 문제를 재현하기 어렵다.

### 제안 범위

- 프런트엔드 오류 수집을 추가한다.
  - 앱 로딩 실패
  - 인증 실패
  - 기록 조회·저장·수정·삭제 실패
  - 성장 기록 실패
  - 위젯·푸시 등록 실패
- 개인정보를 제외한 제품 이벤트를 정의한다.
  - 회원가입 완료
  - 아기 생성 또는 초대 참여
  - 첫 기록 완료
  - 기록 타입별 저장
  - 7일·30일 재방문
  - 분석·리듬·성장 탭 사용
  - 알림 권한 결과
- Supabase Edge Function의 발송 성공·실패·지연을 집계한다.
- 앱 버전, 플랫폼, 저장 모드, 오류 코드까지만 수집하고 아기 이름, 메모, 약 이름 같은 원문은 수집하지 않는다.
- 서비스 상태를 확인할 수 있는 최소 운영 대시보드와 주간 점검표를 만든다.

### 완료 기준

- 운영 오류가 플랫폼과 앱 버전별로 검색된다.
- 저장 실패가 발생하면 사용자에게는 이해 가능한 문구가, 운영자에게는 추적 가능한 오류 ID가 남는다.
- 첫 기록 전환율과 7일 유지율을 확인할 수 있다.
- 개인정보처리방침에 실제 수집 항목과 도구가 반영된다.

### 선행 결정

- 분석·오류 수집 도구 선정
- 원문 돌봄 데이터 비수집 원칙
- 이벤트 보관 기간과 접근 권한

## 3. 공동 보호자 관리와 기록 주체 표시

### 사용자 문제

초대 코드로 같은 아기 기록에 참여할 수는 있지만, 현재 화면에서는 참여 중인 보호자 목록, 기록 작성자, 권한 차이, 초대 코드 교체를 확인하기 어렵다. 여러 보호자가 동시에 기록하면 잘못된 기록을 누가 남겼는지보다 “지금 믿어도 되는 상태인지”가 더 중요해진다.

### 제안 범위

- 프로필에 보호자 목록과 역할을 표시한다.
  - 소유자
  - 공동 보호자
- 최근 기록과 기록 상세에 작성자 이름을 선택적으로 표시한다.
- 초대 코드를 재발급하고 기존 코드를 폐기할 수 있게 한다.
- 소유자는 공동 보호자를 내보낼 수 있고, 공동 보호자는 스스로 나갈 수 있게 한다.
- 아기 프로필 수정, 보호자 관리, 아기 삭제 권한을 명시적으로 구분한다.
- 동시에 같은 기록을 수정한 경우 마지막 저장으로 조용히 덮어쓰지 않고 변경 충돌을 안내한다.

### 데이터 영향

- `baby_members`에 역할과 상태 컬럼 검토
- 이벤트의 기존 `user_id`를 작성자 표시 용도로 연결
- 초대 코드 회전 이력 또는 현재 코드 재발급 RPC
- 보호자 탈퇴와 소유권 이전 정책

### 완료 기준

- 사용자는 현재 함께 기록하는 보호자를 확인할 수 있다.
- 각 기록의 작성자를 확인하되 목록 기본 화면이 과도하게 복잡해지지 않는다.
- 폐기한 초대 코드로는 새 사용자가 참여할 수 없다.
- 공동 보호자 제거 후 해당 사용자는 데이터에 접근할 수 없다.
- 소유자 탈퇴 시 공유 아기 데이터가 예상치 않게 함께 삭제되지 않는다.

## 4. 데이터 내보내기·복구·소유권 안전장치

### 사용자 문제

육아 기록은 시간이 지날수록 개인적 가치가 커진다. 현재는 회원 탈퇴 시 삭제 안내는 있지만, 사용자가 직접 백업하거나 잘못 삭제한 계정·아기 데이터를 복구할 경로가 없다. 특히 소유자 계정 삭제가 공유 데이터에 미치는 영향은 더 보수적으로 다뤄야 한다.

### 제안 범위

- 프로필에서 아기별 전체 데이터를 JSON과 CSV로 내보낸다.
  - 돌봄 이벤트
  - 성장 기록
  - 아기 기본 정보
- 회원 탈퇴 전 데이터 내보내기 CTA를 제공한다.
- 아기 삭제와 계정 탈퇴에 유예 기간 또는 soft delete를 적용한다.
- 공유 아기의 소유자가 탈퇴할 때 다른 보호자에게 소유권을 이전할 수 있게 한다.
- 운영 백업과 복구 절차를 문서화하고 정기 복구 테스트를 한다.
- 로컬 미리보기 사용자가 Supabase 계정으로 데이터를 옮길 수 있는 가져오기 경로를 검토한다.

### 완료 기준

- 내보낸 파일만으로 기록 시간, 타입, 주요 값, 작성자를 해석할 수 있다.
- 사용자가 삭제 전 결과와 공유 보호자 영향을 명확히 확인한다.
- soft delete 기간 안에는 운영 절차를 통해 복구할 수 있다.
- 소유권 이전 후 기존 공동 보호자가 계속 기록을 볼 수 있다.
- 시간대가 달라도 내보낸 시각이 왜곡되지 않는다.

## 5. 알림 설정 센터와 리마인드 확장

### 현재 확인

- 수유 간격 저장과 원격 APNs·FCM 발송 기반이 있다.
- 설정 테이블에는 `enabled`가 있지만 사용자 화면에서 알림을 켜고 끄거나 상태를 자세히 관리하기 어렵다.
- 약 기록에는 `medicineNextAt`이 있으나 실제 약 알림으로 연결되지 않는다.

### 제안 범위

- 프로필 또는 별도 설정 영역에 알림 설정 센터를 만든다.
- 수유 리마인드:
  - 켜기·끄기
  - 기준 간격
  - 예정 시각 전후 여유 시간
  - 보호자별 수신 여부
- 방해 금지 시간과 오늘만 일시 중지를 제공한다.
- 약의 `medicineNextAt`을 실제 1회성 리마인드로 연결한다.
- 알림을 누르면 해당 아기와 기록 화면으로 이동한다.
- 발송 실패 토큰은 비활성화하고 재등록 흐름을 제공한다.
- 알림 문구는 의료적 판단처럼 보이지 않게 사용자가 설정한 기준임을 드러낸다.

### 완료 기준

- 앱 화면의 설정 상태와 서버 설정이 일치한다.
- 같은 보호자가 여러 기기를 사용해도 중복 알림 정책이 명확하다.
- 수유 기록을 추가하면 이전 예정 알림이 더 이상 발송되지 않는다.
- 약 알림을 누르면 해당 약 기록 또는 빠른 기록 화면이 열린다.
- 권한 거부 상태에서 설정 이동 방법을 다시 확인할 수 있다.

## 6. 오프라인 기록 대기열과 충돌 처리

### 사용자 문제

현재 오프라인이면 별도 안내 화면으로 전환되고 Supabase 기록을 저장할 수 없다. 병원, 엘리베이터, 이동 중처럼 네트워크가 불안한 순간에도 수유와 기저귀 기록은 계속 발생한다. 사용자는 저장 버튼을 눌렀다면 나중에라도 반영되기를 기대한다.

### 제안 범위

- 오프라인에서도 신규 기록을 로컬 대기열에 저장한다.
- 화면에는 `기기에 저장됨 · 연결되면 동기화` 상태를 표시한다.
- 재연결 시 생성 순서대로 서버에 반영한다.
- 동기화 중복을 막기 위해 클라이언트 생성 ID와 idempotency 정책을 둔다.
- 오프라인 수정·삭제는 2차 범위로 분리하되 처리 정책을 문서화한다.
- 공동 보호자가 같은 기록을 변경했을 때 충돌 해결 기준을 정의한다.
- 동기화 실패 항목을 사용자가 다시 시도하거나 폐기할 수 있게 한다.

### 완료 기준

- 네트워크 없이 기록한 이벤트가 앱 재시작 후에도 남는다.
- 재연결 후 같은 이벤트가 중복 생성되지 않는다.
- 동기화 전 기록도 홈 요약과 최근 목록에 임시 반영된다.
- 실패한 항목과 정상 동기화된 항목을 구분할 수 있다.
- 시간대와 자정 경계 수면 기록이 재동기화 후에도 동일하다.

## 7. 주간 돌봄 리포트와 공유

### 사용자 문제

분석과 리듬 탭은 앱 안에서 상세하게 볼 수 있지만, 한 주를 짧게 회고하거나 배우자·의료진에게 전달하기에는 정보가 흩어져 있다. 사용자는 차트 자체보다 “이번 주에 어떻게 달라졌는지”를 공유 가능한 형태로 원한다.

### 제안 범위

- 최근 7일 리포트를 한 화면으로 제공한다.
  - 분유량과 모유 시간
  - 수유 간격
  - 총 수면과 가장 긴 수면
  - 기저귀 횟수
  - 이유식과 반응
  - 체온 기록
  - 성장 기록 변화
- 기록이 있는 날만 기준으로 계산하고 누락일을 0으로 해석하지 않는다.
- 지난주 대비 변화는 충분한 데이터가 있을 때만 중립적으로 표시한다.
- 이미지 또는 PDF 공유와 CSV 원기록 첨부를 지원한다.
- 특정 기간과 기록 타입을 사용자가 선택할 수 있게 한다.
- 의료적 진단이 아니라 사용자 입력 기록의 요약임을 명시한다.

### 완료 기준

- 7일 동안 데이터가 적어도 과장된 평균이나 경고를 만들지 않는다.
- 공유 결과에서 아기 이름과 민감 정보 포함 여부를 선택할 수 있다.
- 앱 화면과 내보낸 리포트의 합계가 일치한다.
- 한국어 긴 이름과 큰 글꼴에서도 리포트 레이아웃이 깨지지 않는다.

---

## 8. 성장 기록 완성도와 기준선 개선

### 현재 확인

- 성장 기록은 추가와 조회만 지원하며 화면에서 수정·삭제할 수 없다.
- kg, cm, 머리둘레가 하나의 Y축 차트에 함께 표시되어 값의 크기가 다른 지표를 비교하기 어렵다.
- 출생일부터 현재까지의 성장 맥락이나 백분위 기준선은 제공하지 않는다.

### 제안 범위

- 성장 기록 목록과 수정·삭제를 추가한다.
- 몸무게, 키, 머리둘레 차트를 분리하거나 지표 전환 방식으로 바꾼다.
- 월령 기준으로 기간을 보여주고 측정 간격이 불규칙해도 날짜 축을 정확히 사용한다.
- WHO 성장 기준 적용 가능성을 검토한다.
  - 성별과 월령
  - 미숙아 교정 연령 필요 여부
  - 백분위 또는 z-score
- 기준선을 제공할 경우 진단 문구 대신 참고 범위와 출처를 명확히 표시한다.
- 급격한 변화 알림은 충분한 데이터와 검증 없이는 구현하지 않는다.

### 완료 기준

- 잘못 입력한 성장 기록을 수정·삭제할 수 있다.
- 서로 다른 단위가 한 축에서 오해를 만들지 않는다.
- 동일 측정일 중복 입력 정책이 명확하다.
- 기준선 사용 시 계산 출처, 버전, 적용 한계가 화면에 표시된다.

## 9. 아기 단계별 홈·온보딩 개인화

### 사용자 문제

현재 이유식 기록이 한 번이라도 생기면 홈과 분석이 이유식 중심 모드로 전환된다. 하지만 실제 육아는 수유와 이유식을 오랫동안 병행하며, 아기의 월령과 가정별 시작 시점도 다르다. 자동 전환만으로는 사용자의 의도를 충분히 반영하기 어렵다.

### 제안 범위

- 최초 설정 후 핵심 기능을 설명하는 짧은 온보딩을 제공한다.
  - 공동 보호자 초대
  - 첫 수유 기록
  - 수유 알림 설정
  - 위젯 추가 안내
- 홈의 주요 모드를 사용자가 선택할 수 있게 한다.
  - 수유 중심
  - 수유·이유식 병행
  - 이유식 중심
- 첫 이유식 기록 시 자동 전환 대신 병행 모드 제안을 보여준다.
- 아기 월령에 따라 아직 필요하지 않은 기능은 숨기기보다 설정에서 노출 정도를 조절한다.
- 사용자가 언제든 모드를 바꾸고 기존 기록에는 영향을 주지 않게 한다.

### 완료 기준

- 이유식 한 건만으로 수유 정보가 갑자기 뒤로 밀리지 않는다.
- 신규 사용자가 첫 기록과 보호자 초대까지 막힘 없이 완료한다.
- 선택한 홈 모드는 아기별로 저장된다.
- 단계별 안내는 의료적 권고가 아니라 화면 구성과 기록 편의 설명에 한정한다.

---

## 10. 빠른 기록 자동 정렬의 예측 가능성 개선

### 사용자 문제

최근 사용량에 따라 상위 4개 기록 버튼이 자동으로 앞으로 이동하는 기능은 접근성을 높이지만, 사용자가 이 동작을 잊으면 메뉴가 임의로 바뀐 것처럼 느낄 수 있다. 자주 쓰는 버튼의 위치 기억과 개인화가 충돌한다.

### 제안 범위

- 최초 순서 변경 시 한 번만 `자주 쓰는 기록을 앞으로 정렬했어요` 안내를 표시한다.
- 프로필 또는 빠른 기록 영역에서 다음 중 하나를 선택할 수 있게 한다.
  - 자동 정렬
  - 기본 순서 고정
- 선택적으로 1~2개 기록을 직접 고정하고 나머지만 자동 정렬한다.
- 작은 점수 변화로 버튼이 자주 흔들리지 않도록 최소 점수 차이와 갱신 주기를 둔다.
- 자동 정렬은 저장 직후가 아니라 다음 홈 진입처럼 인지 가능한 시점에 적용하는 방안도 비교한다.

### 완료 기준

- 사용자가 현재 자동 정렬 여부를 확인하고 끌 수 있다.
- 같은 기록 이력에서는 순서가 렌더링마다 달라지지 않는다.
- 고정한 버튼은 사용 빈도와 관계없이 지정 위치를 유지한다.
- 순서 변경 후 아이콘, 라벨, 입력 타입 연결이 정확하다.

## 4. 권장 실행 순서

### 1차: 출시와 측정

- 1. Android 운영 출시 완료
- 2. 운영 관측성과 핵심 지표 구축

새 기능보다 먼저 실제 배포와 측정 기반을 확보한다. 이 단계가 없으면 이후 우선순위가 사용자 문제보다 개발 편의에 따라 정해질 가능성이 크다.

### 2차: 공동육아 신뢰성

- 3. 공동 보호자 관리와 기록 주체 표시
- 4. 데이터 내보내기·복구·소유권 안전장치
- 5. 알림 설정 센터와 리마인드 확장
- 6. 오프라인 기록 대기열과 충돌 처리

Infant Time의 차별점은 단순 개인 기록보다 여러 보호자가 같은 상태를 믿고 공유하는 데 있다. 이 단계에서는 기능 수보다 데이터가 안전하고 설명 가능해야 한다.

### 3차: 재방문 가치

- 7. 주간 돌봄 리포트와 공유
- 8. 성장 기록 완성도와 기준선 개선
- 9. 아기 단계별 홈·온보딩 개인화

기록이 쌓인 뒤 얻는 가치를 강화해 장기 사용 이유를 만든다.

### 4차: 소형 UX 안정화

- 10. 빠른 기록 자동 정렬의 예측 가능성 개선

자동 개인화의 장점을 유지하면서 위치 변화에 대한 통제감과 설명을 제공한다.

## 5. 다음 작업 시작 전 권장 결정

첫 구현 스프린트에 들어가기 전에 아래 세 가지를 먼저 확정하는 편이 좋다.
