# 분석탭 이유식 리듬 전환 PRD

## 1. 배경

현재 분석탭의 `오늘의 리듬`은 수유 기록을 기준으로 구성되어 있다.  
하지만 실제 사용자는 수유만 하는 상태에서 이유식을 시작하는 시점으로 이동하며, 이때 가장 궁금한 정보는 수유 패턴보다 이유식 패턴이다.

이 요구는 기존 수유 로직을 수정하지 않고, 이유식을 시작한 아기에게만 별도의 리듬 우선순위를 제공하는 방식으로 해결해야 한다.

## 2. 문제 정의

- 이유식을 시작한 이후에도 분석탭의 메인 정보가 수유 기준으로 유지된다.
- 이유식 기록이 늘어날수록 보호자가 보고 싶은 핵심 정보는 수유량보다 이유식량, 이유식 간격, 이유식 시간대가 된다.
- 현재 구조는 수유와 이유식을 하나의 축으로 해석해, 이유식 시작 이용자의 정보 적합도를 떨어뜨린다.

## 3. 목표

- 이유식을 1회라도 시작한 아기에게는 분석탭의 메인 리듬을 이유식 우선으로 노출한다.
- 수유와 이유식을 섞지 않고, 서로 독립된 개념으로 다룬다.
- 기존 수유 계산, 수유 알림, 수유 중심 데이터는 그대로 유지한다.
- 분석탭에서만 리듬 선택 우선순위를 추가한다.

## 4. 비목표

- 수유 리마인드 로직 변경
- 수유 입력/저장 로직 변경
- 이유식 관련 DB 스키마 강제 마이그레이션
- 수유와 이유식을 하나의 단일 지표로 합산

## 5. 핵심 개념 정의

- `수유 중 아기`: 수유 기록이 있는 아기
- `이유식 시작 아기`: 이유식 기록이 1회 이상 있는 아기
- `이유식 리듬 활성 상태`: 이유식 시작 이후 분석탭에서 이유식이 메인으로 표시되는 상태
- `수유 리듬`: 기존 수유 기준 분석
- `이유식 리듬`: 이유식 기록 기준 분석

## 6. 상태 분리 원칙

- `수유 중`과 `이유식 시작`은 상호 배타 상태가 아니다.
- 이유식을 시작해도 수유는 계속될 수 있다.
- 분석탭에서는 `이유식 시작` 여부만으로 메인 리듬 우선순위를 판단한다.
- 기존 수유 기반 계산식은 수정하지 않는다.

## 7. 우선순위 규칙

### 7.1 메인 리듬 선택

- 선택한 날짜가 이유식 시작 이전이면 수유 리듬을 유지한다.
- 선택한 날짜가 이유식 시작일 이후이면 이유식 리듬을 메인으로 노출한다.
- 이유식 리듬이 활성화되면 수유 리듬은 보조 정보로만 남긴다.

### 7.2 이유식 시작 판정

- 이유식 이벤트가 1회라도 있으면 `이유식 시작`으로 본다.
- 별도의 사용자가 입력하는 플래그가 없어도 현재는 이벤트 이력으로 판정한다.
- 향후 별도 속성이 생기더라도 수유와 독립적으로 유지한다.

### 7.3 이유식 리듬 노출 순서

- 첫 번째 카드: 이유식 또는 수유 총량
- 두 번째 카드: 수면
- 세 번째 카드: 기저귀
- 첫 번째 차트: 이유식 또는 수유 타임라인
- 두 번째 차트: 이유식 또는 수유 간격
- 세 번째 차트: 최근 7일 총량
- 네 번째 차트: 수면
- 다섯 번째 차트: 배변 상태

## 8. 데이터 기준

### 8.1 수유

- 총 수유량
- 수유 횟수
- 마지막 수유 시각
- 평균 수유 간격

### 8.2 이유식

- 총 이유식량
- 이유식 횟수
- 마지막 이유식 시각
- 평균 이유식 간격
- 최근 7일 이유식량 추세

## 9. 화면 정책

- 분석탭 제목은 상태에 따라 변경한다.
  - 수유 우선: `오늘의 리듬`
  - 이유식 우선: `오늘의 이유식 리듬`
- 차트 제목도 동일하게 상태에 맞춰 바꾼다.
- 이유식 리듬일 때는 수유 차트 문구를 노출하지 않는다.
- 이유식 리듬일 때는 수유는 삭제하지 않고 데이터에만 유지한다.

## 10. 상세 정보 요구사항

이유식을 먹이는 엄마의 관점에서 아래 정보가 필요하다.

- 오늘 이유식을 몇 번 먹였는지
- 총 몇 g을 먹였는지
- 이유식 간격이 일정한지
- 어느 시간대에 몰려 있는지
- 수유와 비교해 오늘은 이유식이 중심인지
- 최근 7일 동안 이유식량이 늘고 있는지
- 이유식 기록이 부족한 날인지
- 이유식 시작 직후인지, 패턴이 형성된 상태인지

## 11. 예외 케이스

- 이유식을 1회만 기록한 경우
- 수유는 많지만 이유식은 드문 경우
- 같은 날 수유와 이유식이 모두 있는 경우
- 이유식 기록은 있으나 양이 없는 경우
- 이유식이 시작됐지만 며칠간 기록이 없는 경우

## 12. 비침범 원칙

- 수유 집계 SQL, 캐시, 푸시, 위젯, 알림 로직은 변경하지 않는다.
- 이유식 리듬은 분석탭 렌더링 단계에서만 선택한다.
- 기존 수유 탭/요약/알림 문구는 유지한다.
- 이유식 관련 계산은 별도 계산 경로로 추가한다.

## 13. 수용 기준

- 이유식 기록이 1회 이상이면 분석탭에서 이유식 메인 화면이 보인다.
- 이유식 시작 이전 날짜는 수유 메인 화면이 보인다.
- 이유식 메인 화면에서 수유 문구가 메인으로 남지 않는다.
- 기존 수유 분석은 이유식 미시작 이용자에서 동일하게 유지된다.
- 빌드가 성공해야 한다.

## 14. 구현 메모

- 이벤트 기반 판정이므로 현재 데이터 구조를 그대로 활용할 수 있다.
- 이후 별도 `solid_started_at` 같은 속성을 추가하더라도 기존 규칙과 충돌하지 않도록 분리한다.
- 분석탭 전용 상태 판단 헬퍼를 두어 다른 화면으로 확장되지 않게 한다.
